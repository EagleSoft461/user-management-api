# v1.1.0 Feature Logic Explanation

This document explains the implementation logic and flow of all three features added in v1.1.0.

## 1. Account Deactivation (Soft Delete)

### Logic Flow
```
User Request → Password Verification → Set active=false → Save User
```

### Implementation Details

**Endpoint**: `POST /api/users/deactivate`

**Request Body**:
```json
{
  "password": "user's current password"
}
```

**Process**:
1. User sends deactivation request with their password
2. System retrieves authenticated user from JWT token
3. System verifies the provided password matches user's current password
4. If password is correct, set `user.active = false` (soft delete)
5. Save user to database
6. Return success message

**Security**:
- Requires JWT authentication (user must be logged in)
- Password verification prevents accidental or unauthorized deactivation
- Soft delete preserves data (can be reactivated by admin if needed)

**Key Code**:
```java
public void deactivateAccount(String email, String password) {
    User user = findByEmail(email);
    
    if (!user.isActive()) {
        throw new IllegalStateException("Account is already deactivated");
    }
    
    if (!passwordEncoder.matches(password, user.getPassword())) {
        throw new IllegalArgumentException("Incorrect password");
    }
    
    user.deactivate();
    userRepository.save(user);
}
```

## 2. Password Reset with Token

### Logic Flow
```
Forgot Password → Generate Token (15 min) → Email Token → 
User Submits Token + New Password → Verify Token → Reset Password → Revoke All Refresh Tokens
```

### Implementation Details

**Endpoints**: 
- `POST /auth/forgot-password` - Request reset token
- `POST /auth/reset-password` - Reset password with token

**Forgot Password Request**:
```json
{
  "email": "user@example.com"
}
```

**Response**:
```json
{
  "message": "Password reset token generated. Check your email.",
  "token": "uuid-token-here"
}
```

**Reset Password Request**:
```json
{
  "token": "uuid-token-from-email",
  "newPassword": "newPassword123",
  "confirmPassword": "newPassword123"
}
```

**Process**:

### Step 1: Request Password Reset
1. User provides email address
2. System finds user by email
3. Delete any existing reset tokens for this user
4. Generate new UUID token
5. Set expiry to 15 minutes from now
6. Save token to database
7. Return token (in production, send via email)

### Step 2: Reset Password
1. User submits token + new password + confirm password
2. Validate passwords match
3. Find token in database
4. Check if token is expired
5. If valid, get associated user
6. Encode new password with BCrypt
7. Update user's password
8. **Revoke all refresh tokens** (force re-login for security)
9. Delete used token

**Security**:
- Token expires after 15 minutes
- One-time use (deleted after successful reset)
- Password confirmation required
- All refresh tokens revoked (prevents session hijacking)
- Old tokens deleted when new one requested

**Key Code**:
```java
@Transactional
public void resetPassword(String token, String newPassword, String confirmPassword) {
    if (!newPassword.equals(confirmPassword)) {
        throw new IllegalArgumentException("Passwords do not match");
    }
    
    PasswordResetToken resetToken = passwordResetTokenRepository.findByToken(token)
            .orElseThrow(() -> new IllegalArgumentException("Invalid or expired token"));
    
    if (resetToken.isExpired()) {
        passwordResetTokenRepository.delete(resetToken);
        throw new IllegalArgumentException("Token has expired");
    }
    
    User user = resetToken.getUser();
    String encodedPassword = passwordEncoder.encode(newPassword);
    user.changePassword(encodedPassword);
    userRepository.save(user);
    
    // Security: Force re-login after password change
    refreshTokenService.revokeAllUserTokens(user);
    
    passwordResetTokenRepository.delete(resetToken);
}
```

## 3. Refresh Token Mechanism

### Logic Flow
```
Login/Register → Generate Access Token (15 min) + Refresh Token (7 days) →
Access Token Expires → Use Refresh Token → Revoke Old Token + Generate New Tokens (Token Rotation)
```

### Implementation Details

**Endpoint**: `POST /auth/refresh`

**Request Body**:
```json
{
  "refreshToken": "uuid-refresh-token"
}
```

**Response**:
```json
{
  "accessToken": "new-jwt-access-token",
  "refreshToken": "new-refresh-token",
  "email": "user@example.com",
  "message": "Token refreshed successfully"
}
```

**Process**:

### Step 1: Login/Register
1. User logs in or registers
2. System generates JWT access token (15 minutes validity)
3. System generates refresh token (7 days validity)
4. Delete old refresh tokens for this user (single device support)
5. Save new refresh token to database
6. Return both tokens to client

### Step 2: Refresh Access Token
1. Client's access token expires
2. Client sends refresh token to `/auth/refresh`
3. System verifies refresh token exists in database
4. Check if token is expired or revoked
5. If valid, get associated user
6. Generate new access token
7. **Token Rotation**: Revoke old refresh token
8. Generate new refresh token
9. Return both new tokens

**Token Rotation Strategy**:
- Old refresh token is immediately revoked (marked as used)
- New refresh token is generated
- This prevents token replay attacks
- Each refresh token can only be used once

**Security Features**:
- Refresh tokens expire after 7 days
- Single-use tokens (token rotation)
- All refresh tokens revoked on password reset
- Tokens can be revoked individually or all at once
- Stored in database (can be audited)

**Key Code**:
```java
@Transactional
public AuthResponse refreshToken(String refreshTokenString) {
    // Verify refresh token
    RefreshToken refreshToken = refreshTokenService.verifyRefreshToken(refreshTokenString);
    
    User user = refreshToken.getUser();
    
    // Generate new access token
    String newAccessToken = jwtUtil.generateToken(user.getEmail());
    
    // Token rotation: Create new refresh token and revoke old one
    refreshTokenService.revokeRefreshToken(refreshTokenString);
    RefreshToken newRefreshToken = refreshTokenService.createRefreshToken(user);

    return new AuthResponse(
            newAccessToken, 
            newRefreshToken.getToken(), 
            user.getEmail(), 
            "Token refreshed successfully"
    );
}
```

**RefreshToken Entity**:
```java
public class RefreshToken {
    private String token;          // UUID
    private User user;             // Associated user
    private LocalDateTime expiryDate;  // 7 days from creation
    private boolean revoked;       // For token rotation
    
    public boolean isValid() {
        return !revoked && !isExpired();
    }
    
    public boolean isExpired() {
        return LocalDateTime.now().isAfter(expiryDate);
    }
}
```

## Security Considerations

### Password Reset + Refresh Token Integration
When a user resets their password, all refresh tokens are revoked:
```java
// In resetPassword method
refreshTokenService.revokeAllUserTokens(user);
```

This ensures:
- If someone stole refresh tokens, they become invalid after password reset
- User must re-login on all devices after password change
- Prevents session hijacking after password compromise

### Token Expiration Strategy
- **Access Token**: 15 minutes (short-lived, stored in memory)
- **Refresh Token**: 7 days (long-lived, stored in database)
- **Password Reset Token**: 15 minutes (one-time use)

### Why This Approach?
1. **Short access tokens**: Minimize damage if token is stolen
2. **Long refresh tokens**: Better user experience (don't login every 15 min)
3. **Token rotation**: Prevents refresh token replay attacks
4. **Database storage**: Can revoke tokens server-side
5. **Password reset revokes all**: Security after password compromise

## Database Schema

### PasswordResetToken Table
```sql
CREATE TABLE password_reset_tokens (
    id BIGSERIAL PRIMARY KEY,
    token VARCHAR(255) UNIQUE NOT NULL,
    user_id BIGINT NOT NULL,
    expiry_date TIMESTAMP NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### RefreshToken Table
```sql
CREATE TABLE refresh_tokens (
    id BIGSERIAL PRIMARY KEY,
    token VARCHAR(255) UNIQUE NOT NULL,
    user_id BIGINT NOT NULL,
    expiry_date TIMESTAMP NOT NULL,
    revoked BOOLEAN DEFAULT FALSE,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

## API Usage Examples

### Complete Flow Example

```bash
# 1. Register
curl -X POST http://localhost:8081/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "password123"}'

# Response: accessToken + refreshToken

# 2. Use access token for 15 minutes
curl -X GET http://localhost:8081/api/users \
  -H "Authorization: Bearer <access-token>"

# 3. After 15 minutes, refresh token
curl -X POST http://localhost:8081/auth/refresh \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "<refresh-token>"}'

# Response: new accessToken + new refreshToken

# 4. Forgot password
curl -X POST http://localhost:8081/auth/forgot-password \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com"}'

# Response: reset token (in production, sent via email)

# 5. Reset password (all refresh tokens revoked)
curl -X POST http://localhost:8081/auth/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "token": "<reset-token>",
    "newPassword": "newPassword456",
    "confirmPassword": "newPassword456"
  }'

# 6. Must login again (old refresh tokens invalid)
curl -X POST http://localhost:8081/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "newPassword456"}'

# 7. Deactivate account
curl -X POST http://localhost:8081/api/users/deactivate \
  -H "Authorization: Bearer <access-token>" \
  -H "Content-Type: application/json" \
  -d '{"password": "newPassword456"}'
```
